Composition rules

Which components can nest inside which. What stacking order they sit in. When a deeper interaction would trap the user and what to do instead.

Never use literal z-index values in component CSS · pull from the scale. If a use case needs a value not on the scale, that's a sign the component belongs at a different layer.

The four hard rules

  1. Never nest a modal in a modal. If the user opened a modal and now needs another decision, replace the content of the existing modal (multi-step wizard) · don't stack a second one. The exception: a destructive confirm inside a wizard ("Are you sure you want to discard?") gets a small overlay but uses the same z-index · see Modal sizes.
  2. Never nest a drawer in a drawer. A drawer is a working surface for one task. If sub-work appears, push the new content into the existing drawer with a back affordance · don't open a second.
  3. Tooltips never contain interactive content. They are read-only hint surfaces. If you need a click target, that's a popover (which is a Dropdown). Tooltips also never contain a tooltip.
  4. Toasts never block flow. They auto-dismiss · don't anchor to specific elements · don't contain forms. If the work requires confirmation, use a modal.

Replacing nesting with sequence

When the matrix says no, the answer is almost always: replace the content, don't stack on top of it.

Bad nestingGood replacement
Drawer → opens modal → opens drawerWizard inside the original drawer with step indicator
Modal → "Edit details" opens a second modalThe first modal becomes a 2-step form · same surface
Tooltip with a link insidePopover (Dropdown) · click to open · keyboard accessible
Toast with "Undo" button + confirm modal on clickSnackbar with single-tap "Undo" · no confirm

Focus trap inheritance

Any overlay that takes focus (modal, drawer) traps Tab inside it. When a sub-overlay is allowed (rare · confirm-discard pattern only) the trap moves to the deepest one. On dismissal, focus returns up the stack · never to body.

// Pseudo-flow for the confirm-discard exception:
openWizardDrawer();             // trap: drawer
//   user clicks "Cancel" on dirty form
openConfirmModal();              // trap moves: modal (drawer locked)
//   user confirms or cancels
closeConfirmModal();             // trap returns: drawer
//   user finishes or closes
closeWizardDrawer();             // trap returns: page

Stacking context · the gotcha

A child element with transform, filter, or position: fixed creates a new stacking context. Inside that context, --z-toast won't escape to global top · it's relative to the parent's stacking context.

Practical rule: render overlays (modal, drawer, toast, tooltip) as direct children of <body> via a portal. React: createPortal(modal, document.body). Vanilla: document.body.appendChild().
