Atom · interactive

Switch

Boolean toggle for reversible decisions. Five states: off · on · loading · failed · disabled. For resource on/off where the API call takes 1-5 seconds, the loading state is non-optional — the user must know the request is in flight, not frozen.

Loading · the critical state

When the user clicks a switch that fires an API call (start/stop a resource, save a setting), the switch enters .is-loading immediately. One signal: the thumb becomes a small spinning ring. The track keeps its direction state (no gradient, no pulse). Pointer events disable so the user can't double-toggle. The visible label ("Starting…", "Stopping…") carries the secondary cue.

<label class="switch is-loading">
  <input type="checkbox">
  Starting…
</label>

// JS flow:
// 1. user clicks switch
// 2. add .is-loading to .switch · update label to "Starting…"
// 3. call API
// 4a. success → remove .is-loading · toggle :checked · update label
// 4b. failure → see failed state below

Failed · rollback + shake

If the API call returns an error, the switch enters .is-failed. Track tints orange, a brief shake animation plays, and the switch state SNAPS BACK to what it was before the click. Pair with an inline error row below explaining the failure.

Couldn't start · insufficient capacity in us-east-1. Retry 
<label class="switch is-failed">
  <input type="checkbox">
  Off
</label>
<div class="field-error">
  <svg .../> Couldn't start · insufficient capacity. <a>Retry</a>
</div>

// JS flow on error:
// 1. remove .is-loading
// 2. add .is-failed · stays for 400ms (shake duration)
// 3. setTimeout(400, () => removeClass('is-failed'))
// 4. render error row · keep visible until user dismisses or retries

Sizes

Three sizes for different surface densities. Use .sm in dense table rows, default in detail panels, .lg in settings forms.

Resource toggle · the composed pattern

For the canonical "turn this cloud resource on/off" use case. Combines the switch with status text, a status dot, and optional meta (uptime, cost-while-on). The data-state attribute drives the dot colour and label.

Running Uptime 4h 22m · $0.42/hr
Starting… est. 30s · ETA 11:42
Stopped Last run 2d ago · $0/hr
Failed to start Insufficient capacity in us-east-1. Retry 
<div class="resource-toggle" data-state="on">
  <label class="switch"><input type="checkbox" checked></label>
  <div class="rt-label">
    <span class="rt-state">Running</span>
    <span class="rt-meta">Uptime 4h 22m · $0.42/hr</span>
  </div>
</div>

// data-state values: "on" "off" "loading" "failed"
// Drives dot colour and the rt-state label.

Accessibility

  • Switch is a native <input type="checkbox"> wrapped in <label> — keyboard accessible, screen-reader announces "checkbox, off / on".
  • For finer screen-reader semantics use role="switch" aria-checked="true|false" on the input so it announces as "switch" instead of "checkbox".
  • During loading: add aria-busy="true" to the parent .switch so assistive tech announces "busy". Update the visible label ("Starting…") so sighted users see the same.
  • On failure: announce the error via role="alert" on the error row so screen readers pick it up immediately.
  • Disabled needs a reason. Use aria-describedby pointing to a tooltip explaining "Read-only access — contact your admin."
  • Focus ring · orange 2px outline at 2px offset (system default).

Don't do this

✓ Do
Switch · API call · spinner state · success/fail feedback
Optimistic + honest. User sees the request is in flight.
✗ Don't
Switch flips instantly + you call the API in the background
If it fails, the switch is showing the wrong state. Users lose trust.
✓ Do
Resource toggle with explicit "Stopping… · ETA 30s"
Tells the user the wait is real and gives them an expectation.
✗ Don't
Use a switch to delete something irreversible
Switches are for reversible decisions. Destructive needs a modal with explicit confirm.
✓ Do
On failure: switch snaps back + inline error · user stays in context
Local recovery. No modal, no toast disruption.
✗ Don't
On failure: leave the switch in the new state and show a toast
Toast disappears. User has no idea their toggle silently rolled back later. State and signal must agree.
