Accessibility

The system meets WCAG 2.1 AA across colour, focus, motion, and keyboard. This page is the rulebook devs apply per component · what shortcut activates a control, what ARIA role it needs, when motion must be suppressed.

The four rules · in order of how often you'll forget them

#RuleTest
1Everything operable by mouse must be operable by keyboard.Unplug your mouse. Try the page.
2Every interactive element must show a visible focus ring on :focus-visible.Tab through the page. Always know where you are.
3Every state change communicated by colour must also be communicated by text or icon.Convert the screen to greyscale. Status still parseable?
4Animation pauses under prefers-reduced-motion: reduce.System Settings → Display → Reduce Motion. App still works?

Focus ring · the only one we use

One ring style across the whole app · orange, 2px, with a 2px paper offset so it reads on coloured backgrounds too. Never hide the focus ring with outline: none without replacing it.

:focus-visible {
  outline: 2px solid var(--zop-orange);
  outline-offset: 2px;
  border-radius: inherit;
}
/* Never do this without a replacement: */
button:focus { outline: none; }   /* ✗ */

Motion sensitivity

Every animation in the system honours prefers-reduced-motion: reduce. When set, transitions reduce to opacity-only or are removed entirely. Nimbus stops his idle breathing too.

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}

Colour-blindness · don't rely on green/red alone

~8% of men have red-green colour deficiency. Status badges always pair colour with an icon or text suffix so the meaning survives a greyscale render.
