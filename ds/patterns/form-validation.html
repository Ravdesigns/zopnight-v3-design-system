Pattern · forms

Form validation

When to validate · where the error sits · what it says · how it clears. Forms are the highest-cost interaction in the product · the validation pattern decides whether the user finishes or rage-quits.

The validation timing matrix

Field typeValidate onWhy
Required text · most fieldsBlur · then live on subsequent inputDon't shout at the user mid-typing. Wait until they move on.
Email · URL · regex formatBlur · then liveSame. Live re-check rewards the fix.
Password creationLive · per keystrokeUser wants to see strength meter / rule checks fill in.
Username uniquenessBlur + debounced async (300ms)Server check. Show pending state.
Numeric range · sliderLive (clamped at edges)Value is constrained by the control · no error needed.
Whole formSubmitCatches anything blur missed. Focus moves to first error.

The three states

Default = clean · validation hasn't fired yet. Valid = check after async (uniqueness, format). Error = red border + message.

Error placement · always below, never overlay

PlacementUse
Below the field · 6px gapDefault · everything else
Inline at top of form · alert bannerWhole-form error (auth failure · 500 · validation summary on submit with 5+ errors)
Tooltip on focusNever for errors · only for format hints
Modal · separate pageNever. Don't yank context for validation.

Async validation · username taken example

Checking availability…

300ms debounce after typing stops. Spinner inside the input · helper text replaces with "Available" (success) or "Taken" (error) when done.

Error message copy guide

PatternGoodBad
Tell the user what to do, not what they did"Add at least one team member""Team members field is required"
Plain language · no jargon"Use only letters, numbers, and dashes""Must match /^[a-z0-9-]+$/i"
No exclamation points"Email format isn't valid""Invalid email!"
Don't blame"This couldn't be saved · please try again""You did this wrong"
Include the value if useful"acme prod can't contain spaces""Invalid input"
