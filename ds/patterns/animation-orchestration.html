Animation orchestration

Motion gallery covers individual animations. This page covers how they sequence · route changes, staggered list reveals, modal/drawer choreography. The 3% rule still holds.

Page transition · the standard

Route change = 180ms fade + 2px upward translate. Subtle enough that the eye doesn't track it · firm enough that "something happened".

<main class="page-enter">
  <!-- route content -->
</main>

/* design.css ships .page-enter · drop it on any route outer */
.page-enter {
  animation: page-enter var(--page-fade-in) ease-out;
}

What we don't do: slide transitions across routes, scale, rotation, page flips. Those belong in marketing pages, not the product.

Staggered list reveal

When a list mounts (search results, dashboard widgets, deploy steps), each item fades up 40ms after the previous. Caps at 8 items · the rest appear instantly so we don't make the user wait.

  • acme-prod · us-east-1
  • acme-staging · us-east-1
  • acme-dev · eu-west-2
  • internal-tools · us-west-2
<ul class="stagger-in">
  <li>Item 1</li>  <!-- 0ms delay -->
  <li>Item 2</li>  <!-- 40ms -->
  <li>Item 3</li>  <!-- 80ms -->
  ...
</ul>

Modal · drawer enter/exit choreography

StageElementMotionDuration
OpenBackdropFade 0 → 0.4 opacity180ms
SurfaceSlide / scale in240ms
CloseSurfaceSlide / fade out160ms
BackdropFade out180ms

Backdrop fades a hair longer than the surface · keeps the page context shaded just long enough for the eye to settle. Easing: cubic-bezier(0.16, 1, 0.3, 1) for entering (decelerate), ease-in for exiting.

The 3% rule applied to orchestration

Even when sequencing, no more than 3% of the screen is in motion at once. If you're staggering 10 list items, only the 1–2 currently animating count. If you're page-transitioning, the entire viewport doesn't count · it's a single event.

What to avoid:

  • Parallax scroll on dashboards
  • Continuous "shimmer" effects on multiple panels at once
  • Auto-playing chart redraws every N seconds
  • Toast animations while drawer is also animating

Reduced motion · what happens

When the user has prefers-reduced-motion: reduce:

  • Stagger collapses to 0 · items appear simultaneously in final state.
  • Page transition reduces to opacity-only · 100ms.
  • Modal/drawer skip the slide · fade only.
  • Nimbus idle breathing pauses · he still moves on intent (wave, money) but at half speed.
@media (prefers-reduced-motion: reduce) {
  .stagger-in > *,
  .page-enter { animation: none; opacity: 1; transform: none; }
}

Don't do this

✓ Do
Stagger 4 KPI cards on dashboard load · 40ms apart · done in 160ms
Subtle establishing motion · then content rest.
✗ Don't
Stagger 50 table rows · 150ms apart · 7+ seconds of motion
User waits to scan. Caps + tight steps prevent this.
